## 2. Schemas

**Model-ready example** (`train/validation/test.jsonl`, one JSON object per line):
```json
{"example_id": "century-L2-006-066+1", "instruction": "Classify the following section ... Answer with the category name only.", "input": "Heading: <heading>\n\nText:\n<section text, whitespace-collapsed, <= 2000 chars>", "output": "risk_factors", "label_status": "unverified_rule_label"}
```
`output` is a separate field, so input truncation can never alter the target. The chat template is **not** applied; this is the plain instruction/input/output schema (I could not see your existing training pipeline, so compatibility is not confirmed). Drop `label_status` if your loader rejects extra keys, but keep the caveat.

**Master record** (key fields): `example_id, document_id, source_filename, document_type, document_part, doc_date, company_name, level, parent_section_id, start_page, end_page, start_printed_page, end_printed_page, original_heading, normalized_heading, parent_heading, heading_path, heading_source, section_text_raw, section_text, n_chars, pages[], category, category_proposed[], label_basis, label_rule_id, label_confidence_tier (categorical, NOT a calibrated probability), label_status, review_status, quality_flags[], training_exclusion_reasons[], extraction_method, source_reference, tabular_line_ratio` (+ `toc`, `section_part`, `evidence` where applicable).

## 8. Truncation and tokenizer / target-preservation status

- Input text budget: **2000 characters** (heading budget 300); 937 examples (17.5%) are truncated; 36 headings truncated. Median excerpt 709 chars; median full section 709, p95 4732, max 159,264. Truncation is deterministic (cut at whitespace) and recorded per example in the manifest; full text stays in the master.
- **Tokenizer / chat-template audit: NOT RUN.** No tokenizer was available and the target model is unknown. Token counts and sequence limits are therefore **unknown**; the character budget is a placeholder, not a token-derived limit.
- What *was* verified without a tokenizer: the target is a separate `output` field (never part of truncated text); every output is a valid category; the excerpt equals / is an exact prefix of its source sections (4,425 full + 937 truncated checked).
- To complete this check locally: `python scripts/14_audit_tokenizer.py --model <your model> --max-seq-len <N> --data-dir data/rebuilt_v4`. It checks prompt-prefix consistency, that target tokens decode to the category, and that right-truncation to N would not cut target tokens. I smoke-tested the script only with a toy character tokenizer; that says nothing about your tokenizer.

## 9. Label-quality caveats you must know before training

- Labels come from **chapter titles** (rule C01–C26, K, G, A rules), so a classifier can score well by learning headings. 4.0% of prompts have a heading equal to the chapter title. Report heading-ablated results if you want content-based claims.
- Inherited labels mean many L2 sections in broad chapters (e.g. *Other Regulatory and Statutory Disclosures*, *Issue Procedure*) carry the chapter label whatever their content; `ipo_details` (984) and `legal_and_regulatory` (920) are large for that reason.
- Evaluation against these labels measures agreement with the rules, not correctness.
